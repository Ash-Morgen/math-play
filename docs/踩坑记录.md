## 一、拖拽交互 ⭐

### 1. 拖拽判定太严格，孩子拖不进去
- **现象**：桌面测试全绿，孩子用起来"怎么拖都不对"。
- **原因**：松手时用 `elementFromPoint` 精确判定落点，小孩子手指精度差，偏差十几像素就失败。
- **解决**：松手时若精确落点未命中容器，**向四周扩 30px 就近吸附**（`drag.js` 的 `hitNear`）。
  所有玩法都传 `near:` 参数（10 处全部接入）。容错半径可调 40~50px。

### 2. 连线"根本没连上"（其实是看不见）
- **现象**：功能正常、点数正确，但用户反馈"线没连上"。
- **原因**：线宽只有 3px，画在两列卡片中间的窄缝里，且无端点标记。
- **解决**：线宽 3→4px、**两端加实心圆点**、加「已连 X / Y」计数条、命中容错 26px。
  教训：**功能正确 ≠ 用户看得见**。

### 3. ⭐ `pointerdown` 里的 `preventDefault()` 会杀掉 `click`
- **现象**：为加"点两下连线"（移动端兜底交互），桌面用 `el.click()` 测试全部通过，**手机上完全失效**。
- **原因**：`pointerdown` 上调用 `preventDefault()` 会阻止浏览器合成后续的 `click` 事件。桌面测试用 `el.click()` 直接触发，绕过了整个事件序列，所以测不出来。
- **解决**：移除 `pointerdown` 的 `preventDefault()`，防滚动交给 `touch-action:none` 和 `touchmove`。
  **验证方式**：必须用真实点击序列（或真机），不能用 `el.click()`。

### 4. ⭐ 轻点阈值 12px 太苛刻，点击被当成拖拽
- **现象**：手机上一片"点了没反应"。
- **原因**：判断"是点击还是拖拽"用的是「移动 < 12px」，但**真人手指按下会抖 5~15px**，超了就当拖拽处理，然后拖到空白处没反应。
- **解决**：改成看**手指抬起时是否仍在原元素上**（落点自判），距离阈值放宽到 25px。
  ```js
  const moved = Math.hypot(lx - sx, ly - sy);
  let upEl = document.elementFromPoint(lx, ly);
  const stillOnSelf = upEl && (upEl === node || node.contains(upEl));
  if ((moved < 25 || stillOnSelf) && opts.onTap) { opts.onTap(node); return; }
  ```

## 二、移动端适配 ⭐⭐

> 教训总纲：**桌面全绿 ≠ 手机能用**。桌面浏览器天然走 Pointer Events，手机 WebView 可能完全不同。

### 5. ⭐ 飞书/微信内置 WebView 可能不支持 Pointer Events
- **现象**：手机上"怎么拖都没反应"，桌面完全正常。
- **解决**：**同时支持 Pointer Events 与 Touch Events**：
  ```js
  const HAS_PE = typeof window.PointerEvent === 'function';
  const downEv = HAS_PE ? 'pointerdown' : 'touchstart';
  // 触摸事件坐标要取 changedTouches，touchend 的 touches 是空的
  ```
- **验证**：加 `?forcetouch=1` 开关强制走 Touch 分支，用合成 `TouchEvent` 测（否则这条路径**从来没被执行过**）。

### 6. 触摸被浏览器当成页面滚动抢走
- **现象**：拖到一半中断，还连带滚了一下页面。
- **解决**：强制 `touch-action:none`（JS + CSS 双保险）。注意 **CSS 里已有 `touch-action` 声明时，后加的选择器若不同名会被跳过**，要检查是否真的生效。

### 7. `pointercancel` / `touchend` 的坐标常是 (0,0)
- **现象**：被取消的拖拽会把元素吸到屏幕左上角。
- **解决**：取消时用**最后已知位置**兜底，不要直接用事件坐标。

### 8. ⭐ 完全没做窄屏适配
- **现象**：连线卡片在手机上只有 64×65px，手指按下去大部分落在卡片外。
- **解决**：窄屏媒体查询——卡片**填满列宽**（64→124px）、两列间距 40px→12px、拖拽方块加大。
- **做法建议**：不要靠 `min-width` 猜，直接让元素 `width:100%` 填满父容器，窄屏自然变大。

### 9. 排查手机问题需要"可见的证据"
- **解决**：加两个诊断工具
  - `touch-test.html`：一页搞定，点一下 + 拖一下 + 实时事件日志 + 环境信息，让用户截图
  - `?debug=1`：页面上实时打印收到的事件（`pointerdown/touchstart/click`…）

## 三、题目生成 ⭐

> 总原则：**每道题都必须真的有解**，否则孩子会卡死，比没有题更糟。

### 10. 消除棋盘的"死块"
- **原因**：值集里放了无法凑出的数字（如 7~9 关放 `14`，但棋盘里没有因数 `2`），这块永远消不掉、只堆积。
- **解决**：只放**自洽的数**——因数本身 + 两个因数都在范围内的积。`test_match.js` 会校验"每个数字都能被凑出"。

### 11. 分苹果「每盘放 1 个」就判成功
- **原因**：判定只看"每盘数量是否相同"，池里还剩 12 个苹果也算过。
- **解决**：必须**池子清空 + 每盘一样多**才算完成。

### 12. 连加连减算出负数
- **现象**：出现 `30 + 11 − 58 = -17`，二年级不学负数。
- **原因**：中间结果没约束。
- **解决**：约束后续运算的数值范围（`c < a+b`）。

### 13. ⭐ 退位减法出现「25 − 32」
- **原因**：只约束了个位，没约束十位，导致被减数小于减数。
- **解决**：减法生成时先定两个十位且保证 `ta > tb`（`const ta = ri(4,9), tb = ri(1, ta-1)`）。
- **通用教训**：**加减法生成要同时校验个位和十位**，否则很容易出非正结果。

### 14. 干扰项凑不满 4 个
- **原因**：`est ± 10` 只能产生 2 个值，撞车时就不够。
- **解决**：多档扰动（±10/±20/±30）**加兜底循环**（还差就补相邻数）。

### 15. ⭐⭐ 进位退位的答案**永远是 1**（设计缺陷，不是代码 bug）
- **现象**：孩子反馈"答案永远是一，起不到强化作用"。
- **原因**：题目问「个位满十，要向十位进几？」——**数学上进位永远进 1、退位永远退 1**，答案不可能变，孩子点一次就永远对。
- **解决**：改成问「**需要进位吗**」（要 / 不要），且生成时进位与不进位**各占一半**。实测 400 题：要进位 229 / 不要 171。
- **教训**：出题时要问自己「**这个答案会不会变**」。恒定答案的题毫无练习价值。

### 16. 天平的"命脉"是两边真的相等
- **做法**：`test_modes.js` 里对 `type:'balance'` 专门解析 `leftText` 并**重算一遍**，验证等于 `ans`。这个校验挡住了题目写错的风险。

## 四、动画与反馈

### 17. ⭐ 得分显示延迟 420ms
- **原因**：得分在结算后统一 `render()`，而 render 被放在消除动画的 `setTimeout` 里。
- **解决**：得分/连击**立即更新**，不等动画。
- **教训**：快节奏玩法里，**反馈慢半秒爽感就没了**。

### 18. ⭐ 改了数据没重绘，屏幕与实际不一致
- **现象**：明明盘面有可消除的配对，却点不动。
- **原因**：补块后调用校验函数修改了数据，但**没重新渲染**——屏幕显示的是旧数字，内部数据已变。
- **解决**：顺序必须是「改数据 → 校验 → 渲染」。
  ```js
  refill(); ensureSolvable(); render();   // ✅
  refill(); render(); ensureSolvable();   // ❌ 屏幕上还是旧数字
  ```

### 19. 达标后要干等时间走完
- **现象**：目标 120 分，打到 150 分还得等 60 秒倒计时结束才过关。
- **解决**：**达标那一瞬立即过关**（在命中分支后判断 `levelScore >= target`）。

### 20. 8 位 Unicode 转义 `\U0001F590` 在 JS 里失效
- **原因**：JS 只支持 4 位 `\uXXXX` 或 ES6 的 `\u{1F590}`，写成 8 位 `\U...` 会退化成普通字符，界面显示字面量 `U0001F590`。
- **解决**：改用真实 emoji 字符，或 `\u{1F590}`。

### 21. 反馈要做成"链"而不是一个点
- **做法**：消除类玩法的完整反馈链——**碎裂 → 宝石飞出 → 计分板弹跳 → 飘字 → 连击光晕 → 补块弹出**。
- **理由**：每一步都有视觉确认，孩子眼睛能一路跟着宝石飞到计数区，累积的爽感才出来。
- **实测**：单独"石头变色"完全不够（用户明确反馈"反馈不够"）。

## 五、工程与工具链

### 22. ⭐⭐ `open(path, 'w')` 先清空文件，之后崩溃 = 文件变空
- **现象**：`grade2.html` 变成 0 行，要 `git restore` 才能救回来。
- **原因**：Python 脚本先 `open(p,'w')`（**立即清空**），随后 `write()` 因编码错误抛异常 → 留下空文件。
- **解决**：
  1. **先把内容全部构造好，最后一步才写盘**
  2. 明确编码：`io.open(p, 'w', encoding='utf-8', newline='\n')`
  3. 批量改文件前先 `git commit`（出事了能恢复）

### 23. Python 不接受 JS 的 `\u{}` 转义
- **原因**：写脚本生成 JS 代码时用了 `'\u{}'`，Python 解析不了。
- **解决**：用独立 `.py` 脚本文件（避开 bash heredoc 的引号冲突），或直接写真实字符。

### 24. bash heredoc 里的转义冲突
- **现象**：`<<'EOF'` 里的 `\u{}` 与单引号解析打架。
- **解决**：改用 `write_file` 写独立脚本再执行。

### 25. 其他环境坑（本机）
- `patch` 对个别文件偶发误判 "Binary file — cannot display as text" → 改用 Python 精确字符串替换。
- `write_file` / `patch` 对 `.js` 报 `Cannot find module 'C:\c\Users\...'` 是 **linter 路径 bug 的假错误**，不是真语法错；用 `node --check` 复核。
- `~/Documents` 实为 `D:\Files\Documents` 的映射。
- git-bash 下 `curl -o /tmp/x` 后读不到文件，改用当前目录。

## 六、部署

### 26. `git push` 的 TLS 间歇性中断
- **解决**：改用 **GitHub Contents API 直传**（`urllib` + `ProxyHandler({})` 绕开代理）。
- **副作用**：API 重试会生成重复 commit，git 历史里有一堆同名提交，功能无影响。

### 27. ⭐ CDN 缓存不同步，导致"版本号是新的但样式是旧的"
- **现象**：用户说"还是不行"，但版本号确认已更新——因为 **HTML 更新了、CSS 却是缓存的旧版**，出现混搭状态。
- **解决**：
  1. 排查线上问题**永远先确认真实加载到的文件版本**（`curl | grep 关键字`）
  2. 排查完再让用户强刷（下拉刷新两次）
  3. 推送后用循环 `curl` 等待关键字出现再交付

## 七、内容与产品

### 28. 教材版本搞错（这个坑很深）
- **现象**：早期按「沪教版六三制」目录做（复习与提高 / 乘法除法 / 统计 / 几何小实践），后来发现**孩子用的是五四学制**（100 以内加减 / 欢乐购物街 / 表内乘法 / 我的学校我的家 / 分类 / 数学广场），目录**完全不同**，白做一轮。
- **解决**：以 `WorkBuddy/Claw/sh-kg` 的权威清单为准。
- **教训**：**动手前先确认教材版本**。另外清了三个残留文件（`_g2_pages.json` / `_g2_texts.json` / `_g2_units.md`）——它们是人教版的内容，版本不对。

### 29. 玩法会堆积同质化，要定期清理
- **判断标准**：
  1. **形式 + 功能都重复** → 直接删（如"算一算"被"加减天平"完全覆盖）
  2. **形式重复、概念不同** → 保留但换交互形式
  3. **同引擎仅参数不同** → 合并成**关卡递进**（如三个口诀消除 → 一个三关制）
- **实测**：25 个玩法清到 20 个，体验明显更清楚。

### 30. 选择题要尽量消灭，但不必强求
- **做法**：22 个玩法从 17 个选择题改到只剩 1 个。
- **例外**：「算式的读写与名称」这类**概念辨析题**，硬做拖拽反而绕，保留选择题更合适。

## 八、测试脚本自身的坑

### 31. 新增 kind 后测试误报
- **现象**：`[mine-sum] gen 抛异常: m.gen is not a function`。
- **原因**：独立流程玩法（`kind:'mine'`）没有 `gen()`，但测试循环对所有模式都调 `gen()`。
- **解决**：循环开头 `if (m.kind === 'mine') continue;`

### 32. 重写引擎导致测试"抽取失败"
- **原因**：测试脚本靠**文字锚点**截取源码（`indexOf('const EMPTY')`），我把 `const` 改成 `var` 就失效了。
- **解决**：改锚点；同时删除的解构项（如 `starOf`）要从测试里去掉。

### 33. 测试要校验"题目有解"而不只是"格式正确"
- 例：天平要验两边真的相等、付钱要验钱币能凑出价格、分苹果要验能整除。
- **这些校验抓出过真 bug**（退位减法负数、估算干扰项不足）。

## 阶段 1 · 数感训练

目标：给二年级孩子做数学启蒙，替代付费 App（数感星球 VIP）。要求零成本、无广告、题目自己生成。

产出 `index.html` + `app.js`：10 / 20 / 100 以内加减，CPA 三阶段递进（具象实物 → 图形 → 抽象数字）。

**决策**：做成 PWA 而不是原生 App——一套代码手机/平板/电脑通用，加到桌面就能全屏，不用装。

## 阶段 2 · 二年级同步闯关（初版）

按教材目录做单元闯关，产出 `grade2.html`。

**踩的坑**：一开始按「沪教版六三制」目录做（复习与提高 / 乘法除法 / 统计 / 几何小实践），做完发现孩子学校用的是**五四学制**，目录完全不同——100 以内加减法（二）/ 欢乐购物街 / 表内乘法 / 我的学校我的家 / 分类 / 数学广场。

**重做**，以 `WorkBuddy/Claw/sh-kg` 的权威清单为准。这就是「动手前先确认教材版本」这条经验的由来。

## 阶段 3 · 交互大改造：把「点选项」换成「动手操作」

**决策理由**：选择题只练"认出答案"，拖拽/摆放练的是"把答案构造出来"，后者才动脑。而且拖拽有手感、不容易腻。

分三批做完 18 个操作型玩法：

| 批次 | 玩法 | 新引擎 |
|---|---|---|
| ⭐⭐⭐ | 竖式填数、点一点数一数、搭配连线、排一排 | `vfill` `count` `link` `order` |
| ⭐⭐ | 方向迷宫、放在正确方位、排到正确位置、分苹果、人民币换算连线 | `maze` `place` `seat` `group` |
| 剩余 | 算式填空、认币分类、每盘放几个、乘加乘减 | `eqfill` `fill` + classify 支持文字标签 |

**期间引入消除玩法**（借鉴 `math-game-2a`）：点选 3 块凑「因数 × 因数 = 积」，按积的十位数追加消除。写 `test_match.js` 专门验证"值集自洽、棋盘必有解、整局零死局"（实测 7200 步无死局）。

**自测抓到的 bug**：消除值集含死块（不可消的数字会永久堆积）、分苹果每盘 1 个就误判成功。

## 阶段 4 · 方向纠正：不是"都改成拖拽"，而是"创新玩法"

**这个纠正很重要**。我理解成"把所有玩法都拖拽化"，一路改到 18/22 操作型。老板指出：

> 不是把第一章所有玩法都改成拖动式的来增加趣味性，应该是**创新几种玩法**

于是提出 6 个新玩法方案供审核：

| 方案 | 机制 | 成本 |
|---|---|---|
| 🥇 **宝石矿工** | 凑数消除（找两块凑目标数） | 低（复用消除引擎） |
| 🥈 小卖部老板 | 经营角色扮演 + 找零 | 中 |
| 🥉 打地鼠 | 快节奏反应 + 干扰项 | 中 |
| **数字天平** | 物理倾斜表达等号 | 低 |
| 小怪兽赛跑 | 对战 AI | 中高 |
| 过河搭桥 | 路径规划 + 数列 | 中 |

**先做了宝石矿工的可玩原型**（`demo-mine.html`），让老板在手机上试机制——比看文字描述判断得准。

## 阶段 6 · 手机端修复（最难的一段，三轮才通）

这是整个项目最费劲的部分，因为**桌面测试全绿，手机完全不能用**。

**第 1 轮**：怀疑飞书 WebView 不支持 Pointer Events
→ 改成同时支持 Pointer + Touch 事件、强制 `touch-action:none`

**第 2 轮**：还是不行。发现"点两下连线"在手机上失效
→ 原因是 `pointerdown` 里的 `preventDefault()` **阻止了浏览器合成 click**。桌面用 `el.click()` 测试绕过了整个事件序列，所以测不出来
→ 改成引擎**自己识别轻点**（手指移动 < 12px）

**第 3 轮**：仍然不行。用户猜"是不是没做移动端适配"——**猜对了**
→ 用 375px 视口加载，发现连线卡片只有 **64×65px**，手指按下去大部分在卡片外
→ 窄屏适配：卡片填满列宽（64→124px）、间距 40→12px
→ 同时发现 12px 的轻点阈值太苛刻（真人手指会抖 5~15px）→ 改成"抬手时是否仍在原元素上"判定

**沉淀的工具**：`touch-test.html` 自检页、`?forcetouch=1` 强制触摸分支、`?debug=1` 实时事件日志。
**沉淀的经验**：桌面全绿 ≠ 手机能用（见「踩坑记录 · 移动端」）。

## 阶段 7 · 两站剥离 + 家长锁

**两站剥离**：数感训练与二年级原本共用 `styles.css`（等于绑在一起）。
→ 把基础样式**内联进 `grade2.css`**、删掉两边的互跳链接，现在可以分别收藏到桌面。

**家长锁**（按学校进度控制，防超前学习）：
- 单元 **2~5 默认锁定**，单元 1 和 6 开放
- 输入密码 **2468** 解锁，**永久记住**（localStorage）
- 家长报告页可「🔒 重新锁上 2~5 单元」

**期间修的真 bug**：`grade2.js` 把 `window.Sfx`（对象）当函数调用 `Sfx()`，抛 ReferenceError 并**打断后面的 `renderHome()`**——表现为"密码输对了但首页不刷新"。

## 阶段 8 · 第 1 章趣味性 + 一个设计缺陷

用户反馈两件事，第二件特别有价值：

> 第一章趣味性差，而且**进位退位的答案永远是一**，怎么起到强化学习的作用？

查证后发现**不是代码 bug，是题目设计缺陷**：问「要向十位进几」，而数学上进位永远进 1、退位永远退 1，**答案不可能变化**，孩子点一次就永远对。

改造成「**进位还是不进位**」（要 / 不要），且进位与不进位**各占一半**。同时把验算、估算也改成拖数字填空，第 1 章变成 100% 操作型。

**自测抓到**：退位减法会出 `25 − 32`（十位没约束）、估算干扰项凑不满 4 个。

## 阶段 9 · 两个新玩法落地

老板选定「宝石矿工 + 数字天平」，并让我定知识点适配：

| 玩法 | 放在 | 理由 |
|---|---|---|
| 💎 宝石矿工 | **第 1 章** | 凑十/凑整百是数感核心；第 1 章原本没有消除类玩法，不重复 |
| ⚖ 数字天平 | **第 3 章**（后加第 1 章加减版） | 第 3 章 8 个玩法全是"算结果"型，缺讲**等式概念**的 |

**天平的核心设计**：拖错时天平会**真的倾斜**（拖大了右沉、拖小了左沉），孩子能自己判断偏大还是偏小，比单纯判对错有教学价值。干扰项用**典型口诀记错**（`6×3=18` 给 21/12/24）。

天平画了两轮才对：初版横梁、盘、支架三块各飘各的 → 加**吊绳**挂盘 + **立柱从横梁中心向下延伸**。

## 阶段 10 · 反馈强化 + 同质化清理

**反馈强化**（用户："宝石矿工的消除正向反馈感觉还不够"）：
原来只有"石头变色 + 分数默默跳一下"。重建为**完整奖励链**：

```
消除 → 碎裂 → 宝石飞向计分区 → 计分板弹跳 → 飘字 → 连击光晕 → 补块弹出
```

设计逻辑：每一步都有视觉确认，孩子眼睛能一路跟着宝石飞到计数区。

**同质化清理**（25 → 20 个玩法）：

| 删掉的 | 理由 |
|---|---|
| 算一算（拖答案） | 与加减天平完全重复 |
| 验算（拖答案） | 与算一算形式完全相同 |
| 乘法消除 · 2~6 / 7~9 | 合并进三关制 |
| 每盘放几个 | 与分苹果重复 |

**乘法消除升级为最终版**：三关递进（2~6 → 7~9 → 全口诀）+ 移植矿工的反馈链 + **达标即过关**（原来 150 分达标后还要干等 60 秒）。

## 附：给接手者（含 AI 助手）的建议

1. **先读 `README.md` 的「设计原则」和 `docs/踩坑记录.md`**——六条原则和 33 个坑能省掉大量返工。
2. **改题目生成逻辑后必跑 `node test_modes.js`**，它校验"每道题是否真的有解"，这正是最容易出错的地方。
3. **改拖拽相关代码后要用 `?forcetouch=1` 验触摸分支**，桌面浏览器天然走 Pointer 分支，触摸那条路永远不会被跑到。
4. **交付前务必在 375px 窄屏下看一眼**——踩过最大的坑就来自"只在桌面测过"。
5. **推送后 `curl` 核验线上关键字再交付**，并提醒用户强刷（CDN 各文件刷新时间不一）。

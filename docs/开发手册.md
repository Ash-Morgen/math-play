# 开发手册

面向后续开发：架构、引擎 API、如何加新玩法、测试与部署的细节。

---

## 一、架构总览

```
grade2.html
   │  按顺序加载：drag.js → drag-extra.js → balance.js → match.js → mine.js → grade2.js
   ▼
grade2.js
   ├── MODES[]            每个玩法一条配置（id / unit / name / kind / round / gen 或 match / mine）
   ├── renderHome()       首页：6 个单元卡片（含家长锁状态 + 练习统计）
   ├── renderUnit(u)      单元页：列出该单元的所有玩法
   ├── startRound(id)     根据 kind 分流：
   │      · kind:'drag'             → 走 10 题循环（nextQuestion）
   │      · kind:'match'            → startMatch()  限时三关
   │      · kind:'mine'             → startMine()   限时多关
   └── 存储 DB（localStorage: mathplay.g2.v2）
```

**引擎认领机制**：`drag.js` 暴露 `DragEngine.mount(root, q, done)`。
后加载的 `drag-extra.js` 与 `balance.js` 用**包装函数**认领自己的题型：

```js
var orig = D.mount;
D.mount = function (root, q, done) {
  if (q.type === 'balance') return buildBalance(root, q, done);  // 我的
  return orig(root, q, done);                                    // 别人的，转交
};
```

所以**加载顺序不能乱**，且新增引擎要放在 grade2.js 之前。

## 二、玩法的三种 kind

```js
// 1) 拖拽型：走 10 题循环，每题调 gen() 取题目
{
  id: 'balance-add', unit: '1 100以内数的加减法（二）', icon: '⚖', name: '加减天平',
  desc: '拖数字让天平平衡', kind: 'drag', round: 6,
  gen() { return { kind:'drag', type:'balance', prompt, leftText, ans, options }; }
}

// 2) 消除型：限时多关，引擎自己管计时与棋盘
{
  id: 'mul-match', unit: '3 表内乘法', icon: '💥', name: '乘法消除',
  desc: '点选 3 块凑算式，三关递进', kind: 'match',
  match: { rows:8, cols:6, levels:[ {name,factorRange,maxVal,timeSec,targetScore}, ... ] }
}

// 3) 独立流程型：引擎完全接管（宝石矿工）
{
  id: 'mine-sum', unit: '1 100以内数的加减法（二）', icon: '💎', name: '宝石矿工 · 凑数',
  desc: '点两块石头凑出目标数', kind: 'mine',
  mine: { targets:[20,50,100], timeSec:50, cols:4 }
}
```

**选择原则**：需要限时、多关、独立计分的（消除 / 矿工）用独立 kind；按题推进的用 `kind:'drag'`。

## 三、拖拽题型参数表

`gen()` 返回的对象里 `type` 字段决定用哪个渲染器。全部 15 种：

| type | 参数（q = { ... }） | 练什么 |
|---|---|---|
| `vfill` | `prompt, a, b, c, op, hide:'a1'/'a0'/'b1'/'b0'/'c1'/'c0', ans, digits[]` | 竖式填数（隐藏某一位） |
| `carry` | `prompt, a, b, op, need`（need=true 表示要进位/退位） | 判断进位与退位 |
| `eqfill` | `prompt, expr, ans, digits[]` | 算式填空 |
| `classify` | `prompt, items:[{emoji,group}], bins:[{label,accept}]` | 分类（每个筐必须有对应物体，否则是死筐） |
| `pay` | `prompt, price, coins[]` | 拖钱币付钱（coins 必须能凑出 price） |
| `count` | `prompt, items:[{emoji}], groups:[{emoji,label}]` | 点一点数一数 + 统计表 |
| `link` | `prompt, left:[{emoji,label}], right:[{emoji,label}]` | 连线（左右标签不能重名） |
| `order` | `prompt, people:[{emoji,name,rank}]`（rank 越大越高） | 推理排序（**rank 不能重复**） |
| `maze` | `prompt, size, start:{r,c}, goal:{r,c}` | 方向迷宫 |
| `place` | `prompt, items:[{emoji,label,dir}]`（dir ∈ 北/东/南/西） | 方位（**dir 不能重复**） |
| `seat` | `prompt, slots, answer, person:{emoji,name}` | 排到第几个位置 |
| `group` | `prompt, total, boxes, emoji` | 平均分（**total 必须能被 boxes 整除**） |
| `fill` | `prompt, per, boxes, emoji` | 按每份数摆放 |
| `balance` | `prompt, leftText, ans, options[]` | 等式概念（**leftText 必须真的等于 ans**） |

> 每种的实现在 `drag.js`（前 8 种）与 `drag-extra.js`（后 6 种）+ `balance.js`，函数名统一为 `build<Type>`。

### 通用要求（写 `gen()` 时必须遵守）

1. **题目必须有解**——上面的"必须"标注都是硬约束，违反会让孩子卡死。
2. **答案要会变**——不要出现恒定答案（历史教训：问"进几"永远是 1）。
3. **干扰项要像"真实错误"**——天平用的就是典型错记（`6×3=18` 给 21/12/24）。
4. **选项里必须含正确答案**，主流程会补，但自己补更保险（见 `nextQuestion`）。

## 四、加一个新玩法的完整步骤

以"人民币等值天平"（放进第 2 章）为例：

### 1) 复用还是新建引擎？

天平引擎已存在 → **复用**，只写题目生成：

```js
// 在 grade2.js 的 MODES 里加一条
{
  id: 'balance-rmb', unit: '2 欢乐购物街', icon: '⚖', name: '人民币天平',
  desc: '拖等值的钱让天平平衡', kind: 'drag', round: 6,
  gen() {
    const a = ri(1, 9);                 // 1~9 元
    const ans = a * 10;                 // 等值角数
    const set = new Set([ans]);
    let g = 0;
    while (set.size < 4 && g++ < 80) {
      const v = ans + ri(1, 4) * 10 * (rnd(2) ? 1 : -1);
      if (v > 0 && v !== ans) set.add(v);
    }
    return {
      kind: 'drag', type: 'balance',
      prompt: a + ' 元 = 几角？拖一个数到右盘',
      leftText: a + ' 元', ans: ans,
      options: shuffle(Array.from(set))
    };
  }
}
```

### 2) 如果是全新交互 → 新建引擎文件

```js
// my-engine.js
(function () {
  var D = window.DragEngine;
  var U = D._utils;                       // el / dragify / shake / Sfx
  var el = U.el, dragify = U.dragify, shake = U.shake, Sfx = U.Sfx;

  function buildMyThing(q, root, done) {
    var scene = el('div', 'drag-scene');
    scene.appendChild(el('div', 'drag-prompt', q.prompt));
    /* ...构建 DOM、绑定拖拽、判定后调用 done(true/false)... */
    root.appendChild(scene);
  }

  var orig = D.mount;                     // 认领自己的 type
  D.mount = function (root, q, done) {
    if (q.type === 'mything') return buildMyThing(root, q, done);
    return orig(root, q, done);
  };
})();
```

然后三处登记：

1. `grade2.html` 在 `grade2.js` **之前**加 `<script src="my-engine.js"></script>`
2. `sw.js` 的缓存列表加 `'./my-engine.js'`
3. `grade2.css` 加样式（命名前缀，避免撞车）

### 3) 写测试

在 `test_modes.js` 的 `if (q.type === '...')` 链里加一个分支，**重点校验这题是否真的有解**：

```js
} else if (q.type === 'mything') {
  if (!q.options || q.options.indexOf(q.ans) < 0) err(m, '选项里没有正确答案');
  // 例：如果答案要用加法得到，就真的加一遍验证
}
```

### 4) 跑测试 + 上浏览器实测

```bash
node --check drag.js && node --check grade2.js   # 语法
node test_modes.js                               # 题目生成
node test_match.js                               # 若动了消除引擎
```

浏览器里务必验：**桌面 + 375px 窄屏 + 触摸事件分支**（见「踩坑记录 · 移动端」）。

## 五、存储与家长锁

```js
// localStorage key: 'mathplay.g2.v2'
DB = {
  stars: 0,              // 累计星数
  answered: 0,           // 总答题数
  correct: 0,            // 正确数
  days: {},              // 每日记录 { '2026-09-11': {answered, correct, stars} }
  modes: {},             // 每玩法 { modeId: {answered, correct, best} }
  unlocked: []           // 已解锁的单元名（家长锁）
};
```

家长锁实现要点（`grade2.js`）：

```js
const LOCKED_UNITS = ['2 欢乐购物街', '3 表内乘法', '4 我的学校我的家', '5 分类'];
const PASSCODE = '2468';

function isLocked(unit) {
  return LOCKED_UNITS.indexOf(unit) >= 0 && DB.unlocked.indexOf(unit) < 0;
}
// 解锁后：unlock(unit) → DB.unlocked.push(unit) → save() → renderHome()
```

**注意**：单元名是**硬编码字符串**，改名（如给单元加序号）会让已解锁状态失效，改名时要同步 `LOCKED_UNITS`。

## 六、测试脚本机制（改代码时要留意）

两个测试脚本都是**从源文件里截取纯逻辑段**再 eval 的，不是加载整个文件：

```js
const a = src.indexOf('const rnd');                  // 起点锚点
const b = src.indexOf('/* ================= 存储');   // 终点锚点
const { MODES } = new Function(src.slice(a, b) + '\nreturn { MODES };')();
```

**所以以下改动会让测试报"抽取失败"**：

- 起点/终点锚点文字被改（如 `const EMPTY` → `var EMPTY`）
- 被导出的纯函数被删除（如 `starOf` 删了但 `test_match.js` 还在解构它）
- 新增 kind 但没在循环里跳过（如 `kind:'mine'` 没有 `gen()`，会报 `m.gen is not a function`）

对应修法：**改锚点、删解构项、在循环开头 `continue`**。

## 七、部署

### 常规方式

```bash
git add -A && git commit -m "..." && git push origin main
```

### 国内网络备选：Contents API 直传

`git push` 的 TLS 时常被重置。备选方案是直接调 GitHub API：

```python
# 需要环境变量 GH_TOKEN（Fine-grained PAT，对目标仓库有 Contents 写权限）
import os, json, base64, urllib.request
tok = os.environ['GH_TOKEN']; repo = 'Ash-Morgen/math-play'
op = urllib.request.build_opener(urllib.request.ProxyHandler({}))   # 绕开代理
def api(path, method='GET', data=None):
    req = urllib.request.Request('https://api.github.com' + path,
        data=json.dumps(data).encode() if data else None,
        headers={'Authorization': 'Bearer ' + tok, 'User-Agent': 'hermes-agent',
                 'Accept': 'application/vnd.github+json',
                 'Content-Type': 'application/json'}, method=method)
    with op.open(req, timeout=60) as r: return json.load(r)

for f in ['grade2.js', 'grade2.css']:
    cur = api(f'/repos/{repo}/contents/{f}')                    # 取 sha
    api(f'/repos/{repo}/contents/{f}', 'PUT', {
        'message': 'update', 'branch': 'main', 'sha': cur['sha'],
        'content': base64.b64encode(open(f, 'rb').read()).decode()
    })
```

> 用 API 重试时每次都会生成一个 commit，历史里会出现重复提交，功能无影响。

### 推送后要等 CDN 刷新

GitHub Pages 各文件的缓存时间不同，可能出现「版本号是新的、CSS 还是旧的」这种混搭。核验：

```bash
curl -s --noproxy '*' https://ash-morgen.github.io/math-play/grade2.css | grep -c "要检查的关键字"
```

一般 1~5 分钟生效。**排查线上问题时，永远先确认加载到的文件版本。**

## 八、Service Worker

`sw.js` 用 **network-first**（缓存名 `mathplay-v3`）：优先拿网络版本，失败才用缓存。这是为了迭代频繁时不会拿到旧版。

改动了文件清单（新增 js/css）要同步更新 `sw.js` 的 `CACHE_LIST`，否则离线时该文件不可用。

调试期如果怀疑 SW 缓存作祟，可在控制台执行：

```js
const keys = await caches.keys();
await Promise.all(keys.map(k => caches.delete(k)));
location.reload();
```
